# Codex Micro V1.0.0 前开发测试版本演进记录

## 文档说明

本文记录 Codex Micro Mobile 从首次可用版本到 V1.0.0 正式版之前，各个开发测试小版本实际完成的新增、重写、修复、验证结果和遗留问题。

这些 V0.x 版本当时没有建立正式的 Beta 发布渠道。手机安装包主要使用 Android `debug` 构建类型，例如 `CodexMicroMobile-v0.2.4-debug.apk`，并带有 `.debug` 应用 ID；Windows Bridge 则是配套的开发测试构建。因此本文统一称为“开发测试版本”，不再把它们追溯命名为 Beta 版。

- 记录范围：V0.1.0、V0.1.1、V0.1.2、V0.2.0、V0.2.1、V0.2.2、V0.2.3、V0.2.4，以及它们如何收敛为 V1.0.0。
- 证据来源：对应版本源码、构建与测试结果、发布说明，以及 2026-08-10 至 2026-08-11 的电脑与红米 K80 Pro 实机测试记录。
- 术语说明：“桌面 Codex”指 Codex Desktop 当前可见对话；“Bridge”指 Windows 桌面桥接程序。
- 准确性边界：只记录能由源码、测试或实机现象确认的内容；没有可靠证据的发布日期、测试数量或实现细节不作补写。

| V0.2.3 | 错误分类与长回复修复 | 避免误判阻断，改善回复保存与提示 | 部分修复，仍有截断和重连风暴 |

| V1.0.0 | 正式版 UI 收口 | 去除重复回复和伪进度，保留单一完整回复 | 首个推荐日常使用版本 |

## V0.1.0：独立 App Server 首个可运行版本

### 新增与实现

- 建立 Android App、Windows Bridge 和共享协议三部分工程。
- Android 通过局域网 WSS 连接 Bridge；Bridge 再独立启动固定版本的 `codex app-server --listen stdio://`。
- 实现六个任务槽、任务创建、发送、运行中追加指令、停止、分叉、未读状态和真实计划步骤进度。
- 初步接入命令、文件、网络、权限及用户输入等审批类型。
- 建立二维码一次性配对、证书 SPKI 指纹固定、Android Keystore 设备密钥、设备挑战签名和消息幂等机制。
- Windows 端提供 WPF 托盘界面、项目白名单、60 秒配对窗口、mDNS 发现和诊断日志。
- 手机端采用深色开发者工具风格，任务状态使用蓝、绿、琥珀、红、灰等颜色区分。

### 验证结果

- Bridge 单元与集成测试达到 44 项通过。
- Android JVM 测试达到 16 项通过。
- 共享协议 38 个样例和 1 组语义配对校验通过。

### 已知局限

- 该架构只能控制 Bridge 自己创建的后台 App Server 任务，不能接管 Codex Desktop 当前正在显示的对话。
- 依赖特定 Codex CLI 版本，早期发布包还受到 PATH、端口和运行时文件完整性的影响。
- 当时尚未完成真实 Android 设备、锁屏、Doze 和不同 Windows 网络环境的完整验收。
- 同版本后续制作了中文界面构建，但它属于 V0.1.0 本地化包，不单列为新功能版本。

## V0.1.1：部署与局域网连接修复

### 改进与修复

- 将手机手动配对默认 WSS 端口从错误的 `443` 对齐到 Bridge 实际固定端口 `47127`。
- Windows 发布包捆绑已验证的 `codex.exe`，双击启动不再要求用户自行配置系统 PATH。
- 重新制作中文、自包含的 Windows x64 发布包，减少首次运行依赖。
- 对 HTTPS、TLS、WSS 升级、App Server 启动和手机客户端覆盖安装进行联合验证。

### 验证结果

- Bridge HTTPS/TLS 返回正常，WSS 握手达到 `101 Switching Protocols`。
- App Server 能成功初始化并显示已连接。
- Windows 测试达到 45 项通过；Android 构建的 47 个 Gradle 任务完成。

### 暴露出的后续问题

- 发布包最初缺少与 Codex CLI 配套的 `codex-code-mode-host.exe`。
- App Server 虽然完成任务，Bridge 仍可能保留运行状态，随后回到空闲却没有回复内容。
- 手机表现为蓝色“执行中”转成白色“等待开始”，没有收到真实结果。
- 因而 V0.1.1 解决了“装得上、连得通”，但尚未解决任务完成同步。

## V0.1.2：完成状态同步与手机 UI 重做

### 改进与修复

- 将匹配版本的 `codex-code-mode-host.exe` 一并纳入桌面发布包，并校验两个可执行文件的配套关系。
- 补齐 `item/completed`、`turn/completed` 等事件处理，保存并恢复 Agent 回复。
- 任务结束时正确清除活动 Turn，完成任务显示绿色“完成未读”，不再错误回到白色空闲。
- 单条格式异常的 App Server 通知不再导致整个输出监听器退出。
- 手机端从深色主题重做为白色 Material 3 主题。
- 六个任务卡使用整卡状态底色：运行中浅蓝、完成浅绿、待处理浅琥珀、错误浅红、空闲或恢复未知浅灰，同时保留图标和文字。
- 重新打包并排查多余语言资源目录，减少发布包杂项。

### 验证结果

- Bridge 测试达到 50 项通过。
- Android 构建、单元测试、APK 签名和覆盖安装兼容性通过。
- 共享协议 38 个样例继续通过。
- 发布目录对 631 个文件进行了哈希检查，没有发现异常文件。

### 暴露出的产品方向问题

- 手机发出的任务仍运行在 Bridge 私有 App Server 中，桌面当前 Codex 对话不会出现该消息。
- 这与“手机输入等同于在桌面当前输入框输入并发送”的真实需求不一致。
- 仍存在旧任务状态恢复和槽位释放体验问题。
- 由此决定不再继续修补旧架构，而是在 V0.2.0 重写为桌面同步模式。

## V0.2.0：桌面同步模式架构重写

### 重写内容

- 运行时不再创建六个独立 App Server 后台任务，主流程改为控制电脑屏幕上当前打开的 Codex Desktop 对话。
- 手机输入通过经过校验的 Windows UI Automation 写入当前 Codex 输入框并执行发送。
- 手机审批通过长按确认，重新校验当前审批控件后执行等同于电脑确认界面回车的动作。
- 新增停止当前执行、读取当前运行状态和同步最近回复的桌面控制路径。
- 首页由多任务控制台收敛为一个“当前桌面对话”槽位；旧项目白名单和旧任务记录只作为历史数据保留。
- 保留白色主题和整卡语义色设计。

### 安全边界

- 每次发送或审批前都重新确认目标确实是当前可见的官方 Codex 窗口、输入框或审批控件。
- 如果用户在操作前切换了窗口、对话或控件，操作直接取消，不向不确定目标注入键盘事件。

### 验证结果

- 桌面端 52 项测试通过。
- Android 构建、单元测试、APK 签名和启动检查通过。

### 已知局限

- 这是一次架构重写，仍需在真实新版 Codex Desktop 多窗口结构上继续适配。
- V0.1.x 的独立 App Server 发布包不再推荐使用，仅保留历史记录。

## V0.2.1：新版 Codex 多窗口识别修复

### 问题原因

- 新版 Codex Desktop 同时存在两个顶层窗口。
- 旧逻辑可能选中没有输入框的外层窗口，因此 Bridge 显示“桌面同步未就绪”。

### 改进与修复

- 枚举官方 Codex 的可见顶层窗口，不再只取第一个候选窗口。
- 从候选窗口中选择真正包含可用输入框的当前对话窗口。
- 增加对当前输入框的只读识别测试，减少误选其他编辑控件的风险。

### 验证结果

- 现场状态能够稳定显示“桌面同步可用”。
- 桌面端测试达到 54 项通过；Android 构建、单元测试和 APK 签名通过。

### 暴露出的后续问题

- 手机文字能够进入桌面输入框，但模拟回车没有被新版 Codex 接受，消息仍停留在输入框中。

## V0.2.2：真实发送按钮与端到端消息闭环

### 改进与修复

- 放弃不可靠的模拟回车，改为定位当前输入框右侧的官方“发送”按钮。
- 使用 UI Automation 的 `InvokePattern` 精确触发发送按钮。
- 发送后检查输入框是否清空或进入已提交状态，避免把“只写入输入框”误报为发送成功。
- 桌面同步失败原因映射为中文可操作提示，不再只显示通用英文 `INTERNAL`。
- 针对输入框更新与校验之间的竞态，加入最长约 1 秒的内容更新等待。

### 验证结果

- 桌面端测试达到 59 项通过；Android 16 项测试通过。
- 实机第二次发送成功：消息进入当前桌面对话，Codex 返回“收到”，手机也同步到该回复。

### 暴露出的后续问题

- 首次发送可能因为输入框更新太快而校验失败，重试后才成功。
- Android 取消上一轮状态等待时会把 `Job was cancelled` 暴露给用户，容易误解为 Codex 任务被取消。
- 一般内部错误曾被错误归类成“连接已阻断”。
- 长回复在权威快照中可能被 500 字摘要覆盖或截断。
- 真实 Codex 审批缺少稳定、可重复的测试入口。

## V0.2.3：错误分类与长回复保存修复

### 改进与修复

- Android 只把真正的身份认证或证书错误归类为“连接已阻断”，普通 `INTERNAL`、取消或临时桌面状态变化不再永久阻断连接。
- 权威快照不再用较短的回复摘要覆盖本地已经保存的完整回复。
- 手机隐藏内部协程取消文本 `Job was cancelled`，改为中文同步状态提示。
- 继续完善输入框更新等待、桌面消息读取和状态恢复测试。

### 验证结果

- 桌面端测试达到 60 项；其中一项依赖证书环境的测试在受限环境中不能完整运行。
- Android 测试达到 21 项通过。
- 短消息手机到桌面发送闭环通过。

### 实机发现的未解决问题

- 12 条长回复仍可能只显示到第 12 条开头，看不到最后的 `【长回复结束】`。
- 红米 K80 Pro 仅切到后台就可能断开 WSS。
- 电脑端直接发送或 Codex 开始思考时，手机会反复断线并连续重连数十次。
- 重连次数没有在成功连接后归零，后续断线会从累计数字继续显示。
- 真实审批受当时执行策略影响没有稳定出现，因此需要 Bridge 内置的确定性审批测试。
- V0.2.3 是过渡修复版，不作为最终稳定版本。

## V0.2.4：连接、长回复、后台与审批稳定性收敛

### 根因修复

- 查明重连风暴的直接原因：Bridge 会发送合法的 `desktop_ui_status` 事件，但 Android 协议白名单没有接受它。
- 当桌面 Codex 开始思考或状态变化时，手机因此误判协议异常并主动关闭 WSS。
- V0.2.4 在 Android 中正式接入并处理该事件，单个状态事件异常不再导致整个连接被拆除。

### 连接稳定性改进

- 收到权威快照并恢复连接后，将重连计数归零；下次断线重新显示“第 1 次”。
- 同一 epoch 的重复事件直接忽略；发现序号缺口时保持当前 WSS，并通过 `task.read` 修复状态。
- 只有 epoch 真正变化时才要求重新获取完整快照。
- Bridge 对桌面状态持久化和广播进行串行化，补充 WebSocket 关闭原因诊断。
- Android 使用网络状态回调，在 Wi-Fi 恢复时立即触发重连。
- 默认提供持续连接前台服务，并加入红米/HyperOS 后台自启动、电池无限制和最近任务锁定提示。

### 长回复改进

- 完整回复先作为消息正文广播和保存，500 字摘要只用于任务概览。
- Room 数据库保留完整消息；重连或快照恢复后自动读取完整消息。
- 避免长回复被状态快照再次截成摘要。

### 审批测试改进

- Bridge 诊断页新增确定性的“发送手机审批测试”。
- 手机进入确认页后长按约 0.6 秒批准，Bridge 在再次核验绑定关系后启动 Windows 记事本。
- 拒绝操作不会执行记事本启动，用于验证批准与拒绝分支。

### 验证结果

- 桌面端 61 项测试通过，Android 22 项测试通过。
- 红米 K80 Pro 实机验证通过以下场景：
  - 电脑直接输入并发送时，手机继续保持绿色连接。
  - Wi-Fi 关闭再打开后从“重连中 · 第 1 次”开始；再次断网仍从第 1 次开始。
  - 12 条长回复能够显示到末尾标记 `【长回复结束】`。
  - 手机长按批准诊断审批后，Windows 记事本成功打开。

### 收口前剩余的界面问题

- 完成后的同一长回复在任务状态卡和“最近回复”卡中显示了两次。
- 顶部状态卡仍带有持续滚动的进度条，容易被理解为任务尚未完成。
- 这两个问题在 V1.0.0 正式版中完成收口。

## 从 V0.2.4 到 V1.0.0 正式版

V1.0.0 没有再次更换核心架构，而是基于 V0.2.4 已通过的实机链路完成界面和发布收口：

- 完成未读状态卡只显示绿色状态、图标、文字和连接类型，不再重复展示回复正文。
- 完成状态不再显示不定进度条或持续滚动的绿色横杠。
- 完整回复只在“最近回复”卡片中显示一次，并支持完整滚动阅读。
- Android 测试增加到 24 项通过；桌面程序和手机应用版本统一标记为 V1.0.0。
- V1.0.0 成为首个推荐日常使用的版本，V0.1.x 至 V0.2.4 均视为开发测试历史版本。

## 三阶段架构变化

| 阶段 | 手机控制目标 | 主要技术 | 结果 |
|---|---|---|---|
| V0.1.0–V0.1.2 | Bridge 自己创建的 Codex 后台任务 | Codex App Server JSON-RPC/JSONL | 多任务能力完整，但不是用户眼前的桌面对话 |
| V0.2.0–V0.2.4 | Codex Desktop 当前可见对话 | Windows UI Automation + WSS 桥接 | 满足“手机等同桌面输入和确认”的真实需求 |
| V1.0.0 | 稳定的当前桌面对话控制 | V0.2.4 稳定链路 + UI 收口 | 正式推荐版本 |

## 仍需长期关注的兼容性边界

- 红米 K80 Pro / HyperOS 的长期后台连接仍受到系统自启动、电池策略和最近任务锁定设置影响，应用无法完全绕过系统冻结策略。
- Codex Desktop 更新如果改变窗口、输入框、发送按钮或审批控件的 UI Automation 结构，Bridge 需要同步更新识别规则。
- 桌面同步依赖电脑端目标 Codex 对话保持打开且没有被最小化到不可访问状态。
- 当前发布面向个人侧载，不等同于应用商店签名与公开分发版本。

## 发布与留存规则

- 日常使用只推荐 V1.0.0 或后续正式版本。
- 旧开发测试二进制包可以删除，不应再作为回退方案；其功能变化由本文档留存。
- 如需排查回归，应优先比较源码提交、测试报告和本文对应版本条目，而不是重新安装已知存在缺陷的旧包。
