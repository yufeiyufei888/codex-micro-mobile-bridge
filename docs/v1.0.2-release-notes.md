# Codex Micro V1.0.2 更新说明

V1.0.2 是 V1.0.1 实机连通性测试后的阻断问题修复版，重点恢复桌面新回复的可靠实时同步，并收口覆盖安装签名连续性。

## 修复内容

- 修复较短回复或 UI Automation 未观察到“执行中→空闲”状态切换时，Bridge 不读取新回复、手机历史停留在旧消息的问题。
- Bridge 现在独立监听已绑定 Codex rollout 文件的长度和更新时间；文件发生变化即读取 canonical 用户/助手消息，并按 `messageId` 幂等写入与推送。
- 实时监听不再持久化提前到达的 `event_msg` 镜像，避免它与稍后到达的 canonical `response_item` 以不同 ID 显示为两条相同回复。
- 首次绑定使用 8 MiB 尾部窗口恢复历史，后续监听使用 2 MiB 尾部窗口降低持续扫描开销。
- Android `versionCode` 提升到 11、`versionName` 提升到 1.0.2；发布 APK 必须与 V1.0.1 的签名 SHA-256 保持一致，才能覆盖安装并保留配对及历史数据。

## 保留的 V1.0.1 修复

- 完整对话历史页与最近回复入口。
- 状态卡只显示状态，不重复显示完整回复正文。
- Computer Use 审批出现时先识别审批控件，不要求输入框同时可见。
- Windows EXE、窗口和托盘统一图标。

## 验证边界

- .NET 单元与集成测试覆盖会话文件追加、canonical 消息读取、事件镜像抑制、审批分类与既有协议安全规则。
- Android JVM、协议 fixture、APK 构建与签名连续性在发布前执行。
- “电脑真实回复可在手机立即出现”“真实 Computer Use 批准/拒绝”和“覆盖安装保留数据”仍需用户在 Windows + 红米 K80 Pro 上做最终实机验收。
