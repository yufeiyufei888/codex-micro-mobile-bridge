# Codex Micro V1.0.5 更新说明

V1.0.5 针对 V1.0.3/V1.0.4 实机测试中稳定复现的“回复固定落后一轮”问题进行根因修复，并修正电脑与手机对桌面同步可用状态的表达。已经验收通过的局域网配对、手机发送、后台保活、完整历史和真实 Computer Use 审批链保持不变。

## 根因与修复

- 旧逻辑在手机消息刚发送、但尚未写入 Codex rollout 文件的短暂窗口内，会回退并绑定到较旧的最近会话。绑定后不再继续寻找真正包含该手机消息的会话，导致消息 1 的回复只能在发送消息 2 时被补读。
- 新版在等待精确手机提示写入期间不会回退到旧会话；最多等待 45 秒，匹配后才建立会话绑定。
- 桌面会话文件监听改为独立 300ms 轮询，不再与容易变化的 Windows UI Automation 控件树检查共用同一循环。输入框或审批控件短暂刷新时，回复文件同步仍继续运行。
- 每次会话文件变化会重新读取有界 canonical 尾部，SQLite 消息 ID 负责幂等去重，不再把可能落在半行 JSON 中间的字节偏移当作唯一游标。
- 会话候选由 24 个提升到 256 个，并排除 subagent rollout，避免后台子任务较多时挤掉真正的桌面 root 会话。
- 手机保留 Bridge 最近一次权威 `bridge.status`。WSS 已连接但桌面输入框不可用时显示“电脑服务降级”，完整状态刷新后不会擅自恢复成绿色在线。
- Computer Use 审批摘要继续过滤通用控件碎片，按状态、会话、请求标题、请求内容、工作目录和实际操作分层展示。

## 实机验收重点

1. 电脑直接连续发送两条消息，手机不做任何操作，确认两条用户消息和两条 Codex 回复均自动出现。
2. 手机发送消息 1，确认回复 1 自动出现；再发送消息 2，确认回复 2 自动出现，且不依赖下一次发送。
3. 临时切换 Codex 页面或触发审批，确认文件回复同步不中断；若输入框确实不可用，电脑与手机同时显示未就绪/降级。
4. 真实 Computer Use 审批仍需确认：手机出现请求、批准或拒绝只执行一次、审批结束后主页退出待审批。

自动测试不能替代 Windows Codex Desktop 与红米 K80 Pro 的最终联合验收。
