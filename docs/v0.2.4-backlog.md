# Codex Micro V0.2.4 修复清单

## 实施状态（2026-08-11）

- 已修复直接根因：Bridge 合法发送的 `desktop_ui_status` 未列入 Android 白名单，导致桌面一进入思考状态，手机就把正常 `task.state` 当成异常并关闭 WSS。
- 成功收到权威快照后重连次数立即归零；下一次真实断线从第 1 次重新计数。
- 同 epoch 的重复事件直接忽略，序号缺口保持连接并通过 `task.read` 自动校准，不再制造重连风暴；epoch 变化仍要求权威快照。
- 全量快照后自动读取完整消息历史；Bridge 先广播完整回复，再发送 500 字状态摘要，摘要不得覆盖 Room 中的完整正文。
- 配对后默认启用可关闭的前台持续连接，增加网络恢复回调和 HyperOS 后台/省电设置入口。
- Bridge 状态变化改为单队列顺序持久化和广播，诊断日志新增 WebSocket 关闭状态。
- 电脑端“诊断”页新增安全审批测试：手机批准后启动记事本，拒绝不执行。
- 自动验证：桌面构建 0 警告/0 错误、61 项 .NET 测试通过；Android 22 项 JVM 测试与 APK 构建通过。
- 尚需用户在 Redmi K80 Pro 与当前 Codex 桌面版本上完成真机前台、后台、长回复和审批四项验收。

## 已确认问题

### 1. 长回复末尾被截断

- 复现设备：Redmi K80 Pro。
- 现象：桌面 Codex 已生成完整回复，但手机详情页在第 12 条中途结束，缺少末尾的 `【长回复结束】`。
- 验收：至少 20 KiB 的中文回复在实时接收、退出后重新进入、应用重启和权威快照覆盖后均保持完整；摘要字段不得覆盖完整正文。
- 排查重点：桌面会话记录读取上限、`task.message.completed` 完整正文、Room 持久化、快照中的 500 字预览与完整正文合并规则、Compose 文本容器限制。

### 2. Redmi K80 Pro 切到后台立即断联

- 复现设备：Redmi K80 Pro，HyperOS；仅切换到后台，不清理最近任务。
- 现象：WSS 立即断开，回到前台后进入重连流程。
- 当前实现：已有用户主动开启的 `connectedDevice` 前台服务，但入口仅位于设置页，普通配对流程不会明确引导开启。
- V0.2.4 方案：
  1. 配对成功后展示“保持后台连接”引导，用户确认后在应用仍可见时启动前台服务并显示常驻通知。
  2. 在设置页显示前台服务实际运行状态，而不只显示 DataStore 开关值。
  3. 使用 `ConnectivityManager.NetworkCallback` 监听局域网恢复，网络可用后立即触发重连，避免等待指数退避。
  4. 增加 HyperOS 专项引导：允许后台自启动、应用电池策略设为无限制、在最近任务中锁定应用。
  5. 前台服务被系统回收后使用 `START_STICKY` 恢复连接；恢复时先请求权威快照，不沿用过期状态。
  6. 增加前后台切换、锁屏、Wi-Fi 切换和进程被回收后的真机测试记录。

### 3. 桌面进入思考后手机反复断线重连

- 复现设备：Redmi K80 Pro。
- 准确触发顺序：手机原本显示绿色正常连接；用户直接在电脑 Codex 输入框用键盘输入并发送消息，手机没有发起任何操作；桌面开始思考或生成回复后，手机立即显示连接断开，并连续重连几十次（现场截图达到第 42 次）。
- 补充证据：短消息也能触发，不能只归因于长回复或 1 MiB 帧上限；手机离线快照仍能看到刚生成回复的部分预览，说明故障发生在桌面状态/回复向手机广播的下行链路。
- 影响：任务进行中无法稳定接收状态、回复和审批事件；大量重连还可能触发认证、快照和序列号竞态。
- V0.2.4 排查重点：
  1. 在桌面桥接端记录每次 WebSocket 关闭的状态码、方向、消息大小和脱敏关联编号，区分手机主动关闭、服务端关闭、超帧和内部异常。
  2. 在 Android 端记录连接代次、TLS/认证阶段、最后成功事件的 `epoch/seq`、关闭原因和网络状态，避免只显示重连次数。
  3. 检查桌面思考阶段的增量消息、完整消息和权威快照是否超过 1 MiB 帧上限，必要时改为分片或分页，不以断开连接处理正常长回复。
  4. 检查 `task.message.delta`、`task.message.completed` 与快照并发时是否造成序列断档，以及断档后的全量同步是否形成重连循环。
  5. 对认证成功后的瞬时请求取消、快照发送失败和桌面窗口切换使用可恢复状态，不得把普通取消升级为永久阻断。
  6. 重连采用单一连接代次和带抖动的指数退避；网络可用或应用回到前台时立即唤醒，但同一时间只允许一个连接任务。
- 验收：连续执行 10 次、每次回复至少 5 分钟或 20 KiB；手机前台和后台各测试一轮，均不得出现非预期断线、并发重连或超过一次的权威快照恢复。

## 临时使用办法

1. 手机应用进入“设置”，打开“后台保持连接”，并允许通知权限。
2. HyperOS 为 Codex Micro 打开后台自启动，将电池策略设为无限制，并在最近任务中锁定应用。
3. 确认通知栏持续显示 Codex Micro 的连接通知；如果没有常驻通知，说明前台服务尚未启动。
